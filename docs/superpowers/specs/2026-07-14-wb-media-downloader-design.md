# WB 商品媒体下载插件设计

## 背景

在现有 `ozon-seller-helper-ext` 之外新建一个完全独立的 Chromium Manifest V3 插件。插件只服务于 Wildberries（WB）商品详情页，用于一次下载当前商品组全部变体的商品轮播图、卖家详情/富内容图片和商品视频。

新插件不连接 Ozon WebUI、本地服务或任何自建后端，不包含 Ozon、1688、登录、采集入库或 OSS 上传功能。实现可参考现有扩展中已经验证过的 WB `card.json`、变体发现、图片 CDN 和视频归属解析逻辑，但不得复制无关业务依赖。

## 目标

- 仅在 WB 商品详情页显示右下角悬浮下载面板。
- 点击一次后自动发现并处理商品组内全部变体。
- 每个变体分别下载轮播图、详情/富内容图片和视频。
- 直接通过浏览器下载能力保存到分层文件夹，不在内存中打包 ZIP。
- 在页面内显示扫描、解析、下载、重试和完成进度。
- 严格绑定媒体与 `nm_id`，避免不同变体之间串图或串视频。
- 保留一份可核对的下载结果清单。

## 非目标

- 不支持 WB 搜索页、类目页、店铺页、评论区或卖家后台。
- 不下载评论买家秀、推荐商品、头像、图标或其他页面装饰图片。
- 不上传媒体，不创建 Ozon 草稿，不调用项目后端。
- 不提供 ZIP 打包、图片转换、视频转码、去水印或媒体编辑。
- 不保存 WB 账号、Cookie 或浏览历史。

## 项目位置与结构

新项目位于仓库根目录：

```text
wb-media-downloader-ext/
├─ manifest.json
├─ service-worker.js
├─ common/
│  ├─ wb-card.js
│  ├─ media-resolver.js
│  ├─ file-path.js
│  └─ download-plan.js
├─ content/
│  ├─ downloader.js
│  └─ downloader.css
├─ icons/
├─ tests/
├─ package.json
└─ README.md
```

纯解析、路径规划和队列状态逻辑放在 `common/`，避免与 DOM 或 Chrome API 耦合，便于单元测试。`content/` 只负责页面识别、悬浮面板和消息通信。`service-worker.js` 是插件内部按需运行的 MV3 Worker，只负责受控的 WB 数据请求、任务协调和 `chrome.downloads` 调用，不是外部后台服务。

## 权限边界

插件只申请完成任务必需的权限：

- `downloads`：启动、监控、取消下载，以及打开下载文件所在目录。
- `storage`：在 `chrome.storage.session` 中保存当前任务状态，使 MV3 Worker 被浏览器回收或商品页刷新后仍可恢复进度。
- `host_permissions`：只覆盖 WB 商品数据域名和 WB 图片/视频 CDN 域名。
- `content_scripts.matches`：只匹配 `www.wildberries.ru` 的商品详情页。

不申请 `cookies`、`tabs`、`<all_urls>`、Ozon、1688 或 localhost 权限。Worker 的消息接口不接受任意远程 URL；页面只提交商品 ID 和当前页面观察到的资源线索，Worker 必须再次校验协议、域名、资源路径和 `nm_id` 归属。

## 架构与数据流

1. `content/downloader.js` 从当前 URL 提取 `nm_id`，确认页面为 `/catalog/{nm_id}/detail.aspx` 后挂载右下角悬浮面板。
2. 用户点击“下载全部变体素材”。页面脚本读取当前页面已加载资源的只读线索并向 Worker 发送开始任务消息。
3. Worker 解析当前商品的 `card.json`，从 `full_colors`、`colors` 等字段发现变体 ID，去重后保留稳定顺序；至少包含当前 `nm_id`。
4. Worker 对每个变体分别解析商品卡和媒体：
   - 轮播图根据该变体的 CDN 路径及 `photo_count` 生成，保持商品展示顺序并优先最高质量可用版本。
   - 详情图从卖家详情/富内容数据或页面明确属于该区域的资源中提取，排除评论、推荐商品和页面装饰资源。
   - 视频优先使用该变体商品数据或页面资源中的直接 MP4，再探测该 `nm_id` 可用的最高分辨率候选；候选不含当前 `nm_id` 时不得复用。
5. `common/download-plan.js` 对媒体 URL 去重、编号、清理扩展名并生成目标相对路径。
6. Worker 使用并发上限为 3 的队列调用 `chrome.downloads.download`，监听下载完成、失败和取消事件，并持续写入任务状态。
7. 页面脚本订阅任务状态，显示当前阶段、变体、总数、成功数和失败数。
8. 所有媒体处理结束后生成 `下载结果.json`，记录商品、变体、源 URL、目标路径、状态和失败原因。

## 保存结构

每次点击创建独立的时间批次，避免重复下载污染旧目录：

```text
Downloads/
└─ WB下载/
   └─ 商品标题_imt-商品组ID/
      └─ YYYYMMDD-HHmmss/
         ├─ 01_红色_nm-123456/
         │  ├─ 轮播图/
         │  │  ├─ 01.webp
         │  │  └─ 02.webp
         │  ├─ 详情图/
         │  │  ├─ 01.webp
         │  │  └─ 02.jpg
         │  └─ 视频/
         │     └─ 01.mp4
         ├─ 02_蓝色_nm-789012/
         │  ├─ 轮播图/
         │  ├─ 详情图/
         │  └─ 视频/
         └─ 下载结果.json
```

变体目录由序号、可用的颜色/规格名称和 `nm_id` 组成。无法识别名称时使用 `变体NN_nm-{id}`。文件名必须移除 Windows 禁止字符、尾部空格和尾点，并对目录段和完整路径设置安全长度上限。重名时使用浏览器的 `uniquify` 冲突策略。

同一变体、同一媒体类别内按规范化 URL 去重。不同变体即使引用相同素材也分别保存，使任意变体目录都能独立使用。视频只下载可直接保存的媒体文件；如果 WB 只提供不能直接保存的流式播放清单，则将该项记为不支持，不在本插件内转码。

## 页面交互

初始状态只显示“下载全部变体素材”按钮。任务开始后面板展开，显示：

- 扫描商品和发现的变体数。
- 当前解析变体与 `解析完成数 / 变体总数`。
- 当前下载文件与 `下载完成数 / 文件总数`。
- 进度条、成功数、失败数和“停止任务”按钮。

任务完成后显示成功/失败汇总，并提供：

- “重试失败项”：只重建失败媒体的下载队列。
- “打开下载目录”：定位本批次中的已完成文件。
- “重新下载”：创建新的时间批次，不覆盖上一次结果。

任务进行中禁止重复启动。页面刷新后从 `chrome.storage.session` 恢复当前任务视图。如果用户切换到了另一个 WB 商品，面板只展示新页面商品；旧任务仍由 Worker 完成，但不会被误认为当前商品任务。

## 下载队列与容错

- 商品数据解析采用有节制的串行或小并发请求，避免对 WB 接口突发请求。
- 媒体下载并发上限为 3。
- 单个媒体下载失败后自动重试两次；重试仍失败时记录原始错误并继续其他文件。
- 单个变体解析失败时记录该变体错误并继续处理剩余变体。
- 商品明确没有视频时记录“无视频”，不计为失败。
- 用户停止任务时取消尚未开始和正在进行的插件下载，不删除已经完成的文件，并生成当前结果清单。
- WB 域名、接口或媒体路径变化时，错误必须显示在页面汇总和结果清单中，不得无提示地把其他变体资源当作回退结果。

## 复用现有 WB 经验

新项目可参考 `ozon-seller-helper-ext/common/wb.js`、`common/collect-flow.js` 和相关测试中的以下做法：

- 从商品 URL 提取 `nm_id` 并限定商品详情页。
- 从 `full_colors`、`colors` 发现变体并对每个变体单独解析。
- 优先使用页面实际加载的 `card.json` 地址，并保留受控的 WB CDN 回退解析。
- 根据 `vol`、`part`、`photo_count` 生成轮播图地址。
- 视频 URL 必须与目标 `nm_id` 匹配，拒绝跨商品或跨变体复用。

只复用或重新实现上述纯逻辑，不引入现有扩展的 Ozon Bridge、汇率、草稿、OSS、登录、弹窗或采集流程。

## 测试与验证

使用 Vitest，按测试先行方式覆盖：

- WB 商品 URL、`nm_id` 和商品页识别。
- `card.json` 资源线索校验和 WB 域名白名单。
- `full_colors`、`colors` 变体发现、去重和稳定排序。
- 每个变体的轮播图顺序和最高质量候选。
- 详情/富内容图片提取，以及评论、推荐和装饰图片排除。
- 视频候选优先级、分辨率选择和 `nm_id` 严格绑定。
- Windows 文件名清理、路径长度限制和下载目录规划。
- 下载队列并发限制、自动重试、失败继续和停止任务。
- 任务状态持久化、页面进度更新和失败项重试。
- Manifest 权限边界和消息入参安全校验。

自动验证命令包括定向 Vitest、完整 `npm test`、关键 JavaScript 文件 `node --check` 和 Manifest JSON 解析。自动测试通过后，使用至少一个含多个变体、详情图和视频的真实 WB 商品页手动验证，检查所有目标文件可打开、变体未串素材、目录与结果清单一致。

## 验收标准

- 在 WB 商品详情页右下角能看到下载面板，其他页面不显示。
- 点击一次能够发现当前商品组全部可解析变体。
- 每个变体都有独立目录，轮播图和详情图按顺序保存，存在视频时保存到该变体的视频目录。
- 多变体测试商品不存在串图或串视频。
- 评论买家秀、推荐商品和页面图标不会被下载。
- 页面实时显示扫描和下载进度，可停止、重试失败项并打开下载目录。
- 个别变体或媒体失败不会阻断其余下载，`下载结果.json` 可核对成功和失败项。
- 插件不依赖外部服务器，不包含 Ozon 业务，不申请超出 WB 下载所需的权限。
- 自动测试和真实 WB 商品页手动验证均通过。
