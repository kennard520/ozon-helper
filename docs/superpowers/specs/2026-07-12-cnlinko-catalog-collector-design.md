# 凌科产品目录全量采集设计

## 目标

从凌科中文站 `cnlinko.cn` 全量采集公开产品数据，并用英文全球站
`cnlinko.com` 补充适合后续翻译成俄语 Ozon Listing 的英文文本。产物保存到本地，
包含产品、型号、参数、图片及全部公开资料，并支持重复运行和断点续传。

## 数据范围与权威来源

- 中文站是分类、产品、型号、技术参数和资料文件的权威来源。
- 英文站按标准化型号匹配，只补充英文名称、描述、卖点和参数术语。
- 采集连接器、电缆组件、线缆、配件及网站产品中心下后续发现的公开分类。
- 采集产品详情页、具体型号、型号与产品/系列/分类的关系及全部可见字段。
- 字段包括但不限于名称、型号、系列、分类、规格、认证、芯数、额定电流、
  额定电压、材质、接口类型、接线类型、连接方式、卖点、描述和来源链接。
- 下载主图、图库、详情图、尺寸图、应用场景图及其他产品相关原图。
- 下载 PDF、DWG、STEP，以及采集期间发现的其他公开产品附件。
- 不采集需要登录、验证码、付费或绕过访问控制才能获取的内容。

## 采集策略

采用“接口优先、页面补充”：先调用产品列表和下载中心使用的公开分页接口，建立
分类、产品和型号队列；再抓取详情页补齐参数、图片和附件。英文站以中文站型号集合
为边界进行匹配，避免无目标地镜像整个站点。

采集器遵守站点公开访问规则，使用保守并发、请求间隔、超时和指数退避。列表页、
详情页及文件下载都记录状态；重启后跳过已经校验成功的内容，只重试失败或变化项。

## 本地目录与输出

默认输出目录为 `data/cnlinko_catalog/`，并确保采集产物不进入 Git：

```text
data/cnlinko_catalog/
├── catalog.xlsx
├── catalog.csv
├── manifest.json
├── products/
│   └── <normalized-model>/
│       ├── product.json
│       ├── images/
│       ├── documents/
│       └── source/
└── reports/
    ├── failures.csv
    ├── missing_files.csv
    └── cn_en_differences.csv
```

`catalog.xlsx` 是面向人工筛选和 Ozon Listing 准备的主索引；`catalog.csv` 提供通用
交换格式；`product.json` 保存每个型号的完整结构化数据；`manifest.json` 保存采集版本、
时间、数量、内容哈希和续传状态。

## 去重与关联

- 型号经过大小写、空白和常见分隔符规范化后用于中英文匹配，但保留站点原文。
- 图片和附件按内容 SHA-256 去重；同一文件属于多个型号时，在索引中保留全部关系。
- 明显的低分辨率缩略图在已有同内容或同源高清图时不重复保留。
- 中英文参数冲突不自动覆盖：中文值进入主字段，英文值及差异写入差异报告。
- 文件名经过 Windows 安全化处理，原始文件名、URL、类型和哈希保存在元数据中。

## 错误处理与可恢复性

- 网络超时、限流和临时服务错误自动重试；永久失败写入失败报告。
- 单个页面或文件失败不阻断其他产品。
- 下载先写临时文件，完成并校验后原子改名，防止把半截文件视为成功。
- 检查响应类型、文件大小和哈希，避免把错误 HTML 保存成 PDF、DWG 或 STEP。
- 每次运行输出新增、更新、未变化、失败和去重数量。

## 验证与完成标准

- 使用已知分类和下载中心分页结果核对列表总数与采集总数。
- 对每个产品检查至少存在型号、名称、来源页；缺失项进入报告而不是静默丢弃。
- 抽查多个系列，核对页面参数、图片和附件与本地索引一致。
- 验证 PDF 文件头，检查 DWG/STEP 的扩展名、响应类型和非空内容。
- 验证重复运行不会重复下载未变化文件，失败项可以单独重试。
- 最终报告产品数、型号数、图片数、资料数、去重数及失败数。

## 非目标

- 本阶段不生成俄语 Listing，也不直接上传 Ozon。
- 不对图片进行抠图、翻译或版式重制。
- 不抓取新闻、招聘、解决方案等与产品目录无直接关系的站点内容。
