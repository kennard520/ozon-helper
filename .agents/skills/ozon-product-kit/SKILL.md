# ozon-product-kit — Ozon 商品卡一键生成 Skill

## 目标

本 skill 是 Ozon 商品卡总控工作流。用户只需要提供以下任意一种输入：

- 一张或多张产品图
- 一个商品链接
- 一段简单中文说明
- 产品图 + 少量参数
- 商品链接 + 少量补充说明

本 skill 自动完成：

1. 识别商品和图片中的可见信息
2. 提取图片里的尺寸、参数、卖点、型号、材质、包装清单等文字信息
3. 区分“已确认 / 图片识别待核对 / 待确认”
4. 设计 10 张 Ozon 商品卡图片方案
5. 调用豆包内置图片工具（`image_gen` 文生图 / `image_edit` 参考图编辑）逐张生成图片
6. 生成俄语 Ozon 标题、简介、卖点、商品描述、营销文本
7. 生成 30 个以内俄语主题标签
8. 生成 Ozon 富文本内容结构
9. 输出完整路径、文案和复核清单
10. 设计并生成 AI 商品视频（默认 1 条主视频/视频封面，可选场景/功能视频），遵守"Ozon 视频要求"

# 依赖（出图后端）

本 skill **不依赖任何外部出图脚本**（已弃用旧的 `gen-image/generate.py` 及其第三方 API）。
直接使用豆包内置图片工具：

- `image_gen`：文生图。无产品图时做概念图 / 场景氛围图 / 干净排版底图。
- `image_edit`：参考图编辑（图生图）。**有产品图时一律走这条**，把产品实拍图作为参考锚点，保持产品外观一致。

入参映射（旧 gen-image CLI → 豆包工具）：

| 旧 gen-image 参数 | 豆包工具对应 |
|---|---|
| `--mode create` | `image_gen(prompt, width, height, model_version)` |
| `--mode edit --image X` | `image_edit(prompt, image_reference_url_list=[X_url], width, height, model_version)` |
| `--mode mask`（去水印 / 换背景 / 局部改） | `image_edit`，在 prompt 里用自然语言圈定只改哪一块，无独立 mask 参数 |
| `--size 1024x1536` | `width=1024, height=1536`（3:4 竖版） |
| `--n 1` | 每次 request 只出 1 张 |
| `--name 01_main.png` | 生成后把返回 URL 落盘为该文件名 |

固定出图参数：

- `width=1024, height=1536`（Ozon 3:4 竖版；用户指定其它比例时再改）。
- `model_version` 默认 `seedream_5.0_flash`；主图 / 高质量场景图可升级 `seedream_5.0_pro`。

本地产品图是参考图时的前置步骤（必须）：

1. 本地图片不能直接塞进 `image_edit.image_reference_url_list`，必须先调用 `FileBatchUpload` 把本地产品图上传，拿到 `https://` URL。
2. 把该 URL 填进 `image_reference_url_list`。
3. `image_reference_url_list` 最多 10 张；产品图 + 场景图可一起传入做多图参考。

落盘（必须）：

1. 生图工具返回的是图片 URL，不是本地路径。
2. 用 `curl -L -o "<输出目录>/images/<文件名>" "<图片URL>"` 下载到 `images/` 目录。
3. 以落盘后的本地路径为准写入 image_results.md / run_report.md；不要把临时 URL 当最终产物交付。

用户可以只发一句话，例如：

```text
Ozon一键生成：
这张图是三脚架自拍杆，参数按图里识别，生成整套 Ozon 商品卡。
```

处理原则：

1. 不要求用户写长提示词。
2. 自动从图片和文字中提取商品信息。
3. 图片里能看清的尺寸、参数、卖点要提取出来。
4. 识别不清的内容不能当作确定信息。
5. 缺少真实产品图时，不生成冒充实物的主图。
6. 缺少参数时不中断流程，但要标记“待确认”。

# 支持的输入模式

## 1. 产品图模式

用户上传一张或多张产品图。

处理方式：

1. 识别商品类型、颜色、结构、可见配件、可见文字。
2. 对图片进行视觉分析和文字提取。
3. 提取图片中出现的尺寸、参数、卖点、型号、材质、包装清单、安装步骤等。
4. 将清晰可见且合理的信息列入“已确认信息”。
5. 将模糊、不完整、有遮挡或可能识别错误的信息列入“图片识别待核对”。
6. 将图片无法确认的信息列入“待确认信息”。
7. 生成图片时优先使用 `image_edit`，并把产品图作为参考图。
8. 不要用纯 `image_gen` 重新画产品主图。
9. 不要虚构图片中不存在的配件、功能、品牌和参数。

## 2. 链接模式

用户提供商品链接。

处理方式：

1. 尝试读取链接内容。
2. 提取商品标题、主图、详情图、参数、包装清单、卖点。
3. 如果页面有多张图，优先选择最清晰、最接近商品白底图的图片作为产品参考图。
4. 如果链接无法访问、需要登录、验证码或反爬，则提示用户上传产品图或截图。
5. 链接中没有明确写出的参数不能当作确定信息。
6. 不要复制竞品品牌、店铺名、水印、公司名和侵权词。

## 3. 简单文字模式

用户只提供一句话，例如：

```text
280KG 防水磁力锁，生成一套 Ozon 商品卡。
```

处理方式：

1. 根据文字生成商品理解和图片方案。
2. 缺少产品图时，只能生成方案、文案和场景示意图。
3. 主图、细节图、尺寸图必须提醒用户需要真实产品图。
4. 不要生成“看起来像真实产品”的主图来冒充真实商品图。
5. 所有无法确认的信息写入“待确认”。

## 4. 图 + 参数模式

这是推荐模式。

用户提供产品图，同时补充参数，例如：

```text
商品：黑色三脚架自拍杆
参数：120cm，24cm收纳，7节伸缩，1/4螺丝，铝合金+ABS
要求：生成10张Ozon商品图、俄语listing、标签、富文本
```

处理方式：

1. 产品图作为外观参考。
2. 用户参数作为已确认信息。
3. 图片中文字和参数作为补充来源。
4. 根据商品类型自动设计 10 张图。
5. 调用豆包 `image_edit` 逐张出图。
6. 生成俄语商品资料。

# 图片文字 / 尺寸 / 卖点提取规则

这是本 skill 的关键规则。

## 必须从产品图中提取的信息

如果图片中出现以下内容，必须尝试提取：

- 商品名称
- 型号
- 尺寸，例如长度、宽度、高度、厚度、直径
- 重量
- 材质
- 颜色
- 节数、档位、数量
- 功率、电压、电流、电池容量
- 接口类型，例如 Type-C、USB、1/4 螺丝
- 防水、防尘、耐高温、承重等功能卖点
- 适用设备
- 适用场景
- 安装步骤
- 包装清单
- 警示说明
- 认证标志

## 提取结果必须分级

提取后生成 `image_extracted_info.md`，结构如下：

```markdown
# 图片识别信息

## 图片来源

## 可见商品结构

## 图片文字提取表

| 原图文字 | 识别结果 | 中文解释 | 俄语可用表达 | 可信度 | 使用状态 | 备注 |
|---|---|---|---|---|---|---|

## 已确认信息

## 图片识别待核对

## 明确禁止复制的信息

## 待确认信息
```

## 可信度规则

### 高可信，可作为已确认信息

满足全部条件才可作为已确认信息：

1. 图片中文字清晰可读。
2. 数字和单位完整，例如 `120cm`、`24cm`、`207g`。
3. 与商品外观和类别不冲突。
4. 不是价格、联系方式、二维码、店铺名、水印、竞品品牌。

### 中可信，作为“图片识别待核对”

以下情况不能直接写成确定卖点：

1. 字体模糊。
2. 被遮挡。
3. 数字不完整。
4. 单位不清楚。
5. 可能是图片背景里的无关文字。
6. 参数与商品外观看起来冲突。

### 低可信，不能使用

以下内容必须丢弃：

1. 价格。
2. 折扣。
3. 联系方式。
4. 店铺名。
5. 公司名。
6. 水印。
7. 二维码。
8. 平台促销标签。
9. 竞品品牌。
10. 识别明显错误的乱码。

## 图片中文字如何使用

1. 可以把中文参数翻译成俄语 listing。
2. 不要把中文直接放到最终 Ozon 文案里。
3. 不要让 AI 在生成图里重新绘制中文。
4. 尺寸、参数、卖点可以用于文字内容，但必须注明来源是图片识别。
5. 对重要参数，最终输出中要提示人工复核。

示例：

如果图片中写着：

```text
120cm / 24cm / 7节伸缩 / 1/4螺丝 / 207g
```

可以在 `image_extracted_info.md` 中写：

```markdown
已从图片中识别到：展开高度 120cm、收纳长度 24cm、7 节伸缩、1/4 螺丝接口、约 207g。建议人工复核后用于最终上架参数。
```

俄语 listing 可写：

```text
Высота в разложенном виде — до 120 см, длина в сложенном виде — около 24 см, 7 секций, универсальный винт 1/4".
```

但生成图片时不要让 AI 直接写这些数字。

# 信息可信度分级

所有商品信息必须分为四类。

## 用户确认信息

用户明确提供的信息。优先级最高。

## 图片识别信息

从产品图文字、参数表、包装图或说明图中识别的信息。

图片识别信息可以使用，但重要参数需要在最终结果中提示人工复核。

## 合理推断信息

根据外观和商品类别可以合理判断的信息，例如：

- 黑色外壳
- 三脚架结构
- 可伸缩结构
- 玻璃门安装场景
- 桌面使用场景
- 便携收纳场景

合理推断信息可以谨慎写入描述，但不要写成绝对承诺。

## 待确认信息

以下信息如果用户、链接、图片都没有明确提供，不得编造：

- 净重
- 尺寸
- 材质
- 承重
- 功率
- 电池容量
- 防水等级
- 认证
- 包装清单
- 是否含遥控器
- 是否含手机夹
- 是否含安装螺丝
- 是否支持某具体型号
- 质保时间
- 品牌授权

待确认信息必须在最终结果中单独列出。

# Ozon 图片硬性要求

## 官方规格（来源：Ozon 帮助中心《对图片的要求》）

本地知识库：`ozon-help-kb/markdown/products/requirements/media/image-requirements.md`

| 参数 | 要求 |
|---|---|
| 格式 | JPEG / JPG / PNG / HEIC / WEBP |
| 比例 | 全部类目竖版 3:4（主图不符会被 8 点拉伸或上下留白） |
| 分辨率 | 服装/鞋子/配饰 ≥900×1200px；其他类目 200×200 ~ 4320×7680px |
| 大小 | ≤10MB |
| 数量 | 主图 1 张；附加图 ≤29 张（建议 ≥2 张）；**商品图片总数不得低于 6 张（用户业务硬性要求）** |
| 主图 | 1 张、彩色、清晰、无水印、无文字，商品完整正面展示 |
| 附加图 | 无水印；与主图商品一致；不得含联系方式/链接/促销 |
| 禁止 | 黑白/模糊/低质照片、家居背景（地毯/家具阴影）、3D 草图、酒类、不含商品的图、他人商品图、暴力内容；18+ 商品私密部位须模糊处理 |

所有商品图必须遵守：

1. 单张独立图片，不要拼宫格。
2. 竖版 3:4。
3. 推荐尺寸：`1024x1536`。
4. 背景白色或浅色。
5. 白色或透明商品可使用深色背景。
6. 服装、鞋类、配饰类目可使用灰色背景 `#f2f3f5`。
7. 图片清晰，不要模糊。
8. 不要黑白照片。
9. 不要价格。
10. 不要折扣。
11. 不要联系方式。
12. 不要链接。
13. 不要二维码。
14. 不要购买引导，例如“购买”“立即下单”“联系卖家”。
15. 不要中文。
16. 不要水印。
17. 不要品牌 logo，除非用户明确拥有品牌并要求保留。
18. 不要公司名、工厂名、店铺名。
19. 不要侵权商标。
20. 主图不要大段文字。
21. 主图商品不要贴边，四周保留安全边距。
22. 重要细节不要靠近四角，避免被平台徽章遮挡。
23. 不要虚构配件。
24. 不要虚构功能。
25. 不要让 AI 自动生成复杂俄文和参数数字。

# Ozon 视频要求

来源：Ozon 帮助中心《对视频的要求》《视频封面要求》
本地知识库：`ozon-help-kb/markdown/products/requirements/media/video-requirements.md`、`videocover-requirements.md`

## 商品视频（卡片内视频）

| 参数 | 要求 |
|---|---|
| 格式 | MP4 / MOV |
| 分辨率 | 长边 1080 ~ 1920px |
| 大小 | 电脑经个人中心上传 ≤100MB；其他 ≤5GB |
| 时长 | 8 秒 ~ 5 分钟 |
| 编码 | H.264 / HEVC(H.265) / VP9 / MPEG-4 等常见编码 |
| 上传来源 | 仅 VK Video / Yandex.Disk / Rutube；最多 5 个视频 |
| 内容 | 必须包含所属商品，展示优点和使用示例；音质良好 |

视频内容禁止：

- 脏话、侮辱性言辞；
- 酒、烟；
- 价格、折扣、联系方式、社交网站文字；
- 提及 Instagram / Facebook（Meta，俄罗斯禁止）；
- 物流及退货条件（如"快速物流""明日送到"）；
- 其它平台或店铺广告；
- 个人信息（银行卡号、护照照片等）；
- 身体私密部位、色情声音；
- 俄罗斯法律禁止的信息；
- Ozon 禁售商品。

## 视频封面（代替主图展示的短视频）

| 参数 | 要求 |
|---|---|
| 格式 | MP4 / MOV |
| 大小 | ≤20MB |
| 时长 | 8 ~ 30 秒 |
| 比例 | 竖版 3:4（勿用 16:9 / 9:16，会被大裁剪） |
| 边框/底板 | 禁用 |
| 内容 | 第一帧必须清晰；关键文字大而清晰、防裁剪；无需音轨也能看懂；焦点在商品上 |

注意：视频封面仅显示在商品卡片，不显示在搜索结果页和类目页。

# Ozon 视频生成（AI 设计）

listing 默认包含 AI 商品视频（视频封面 / 主视频）。所有视频生成必须遵守上方"Ozon 视频要求"，并配合全局 skill `doubao-creative-video` 执行。

## 调用前置（必须）

1. 生成前必须先完整读取全局 skill `doubao-creative-video` 的 SKILL.md，按其实行：参数确认 → 分镜表 → `interaction.ask` 生成确认 → 委派生成。
2. 用户明确指定 seedance 2.5 时，同时读取 `seedance-25` skill。
3. 视频工具：`image_to_video`（有产品图时图生视频，保持产品外观一致）/ `text_to_video`（无产品图时做概念/场景）。
4. 本地产品图先 `FileBatchUpload` 上传拿 URL，再作为参考图传入。

## 默认视频方案

| 项 | 默认 |
|---|---|
| 数量 | 1 条主视频（视频封面位）；场景/功能视频按需，一轮最多 2 条 |
| 时长 | 8~15 秒（seedance 2.0 fast）；封面场景如需更长（≤30 秒）须用户明确指定 2.5 |
| 比例 | 3:4（Ozon 商品卡/封面）；用户指定信息流投放时可 9:16 |
| 模型 | seedance 2.0 fast（默认）；seedance 2.5 仅用户明确指定 |
| 字幕/文字 | 默认无字幕；画面文字不使用中文（合规） |
| 语言 | 与用户指令语言一致；无中文文字上屏 |

## 视频方案设计（video_plan.md）

与图片方案同目录输出 video_plan.md，每条视频包含：

- 视频编号与用途（主视频 / 场景视频 / 功能演示）
- 叙事节拍（B01...，围绕商品卖点组织）
- 生成提示词（英文，按 doubao-creative-video 的五段式规则编译）
- 工具：`image_to_video` / `text_to_video`
- 参考图 URL（产品图，如有）
- 时长、比例、模型
- 禁止事项（无中文、无价格、无水印、无品牌侵权）

## 落盘与记录

1. 视频工具返回视频 URL。
2. 下载到 `outputs/ozon/<商品名>_<日期>/video/`（用 curl -L -o）。
3. 写 video_results.md：编号、工具、参考图、落盘路径、时长、重试记录。
4. 交付以落盘本地路径为准，不用临时 URL。

## 视频合规检查

- 时长/比例/格式符合"Ozon 视频要求"（3:4、8~30 秒封面、MP4/MOV）
- 画面无中文、无价格/折扣、无联系方式、无水印、无品牌侵权
- 内容包含商品本身，展示优点和使用示例
- 无脏话/酒烟、无 Meta 平台提及、无物流履约条件、无个人信息、无色情内容等红线
- 主视频首帧清晰（封面位）
- 失败重新生成，每条最多重试 2 次

# 图片文字规则

AI 图片生成不适合直接生成准确俄文、中文、尺寸数字和参数表。

因此：

1. 主图不放文字。
2. 尺寸图只生成干净底图和预留排版区域。
3. 参数图只生成底图，不让 AI 写参数。
4. 富文本底图可以预留标题区、参数区、卖点区，但不要让 AI 写具体文字。
5. 俄文标题、参数、卖点应在后期设计工具中单独排版。
6. 如果用户要求直接出带文字图片，必须提醒：AI 可能生成错误文字，建议后期排版。

- 目标语言：俄语

- 禁止事项
- 输出文件名

## Step 5：为每张图生成英文提示词

每张图提示词必须包含：

- 商品名称

- Ozon 风格

- 1024x1536
- white or light background
- no Chinese text
- no watermark
- no logo
- no QR code
- no price
- no contact information
- keep product consistent with reference image

对于信息图底图，额外加入：


## Step 6：调用豆包图片工具出图

### 前置：本地产品图先上传拿 URL

如果用户给的是本地产品图路径，先调用 `FileBatchUpload` 上传该图，拿到 `https://` URL，记作 `PRODUCT_URL`。无产品图则跳过本步。

### 默认 image_edit（有产品图）

```text
image_edit(
  prompt="<英文 PROMPT>",
  image_reference_url_list=["<PRODUCT_URL>"],
  width=1024, height=1536,
  model_version="seedream_5.0_flash"
)
```

多图合成（产品图 + 场景参考图）：把多张参考图 URL 一起放进 `image_reference_url_list`（最多 10 张）。

### image_gen（无产品图）

仅用于：概念图、场景氛围图、纯干净排版底图——即不要求产品 100% 一致时。

```text
image_gen(
  prompt="<英文 PROMPT>",
  width=1024, height=1536,
  model_version="seedream_5.0_flash"
)
```

### 局部修改（去水印 / 换背景 / 修瑕疵）

豆包无独立 mask 参数，改用 `image_edit` + prompt 用自然语言圈定只改哪一块，例如：

```text
Keep the product exactly unchanged. Only replace the background with pure white.
```

## Step 7：落盘并记录

每次生图工具调用后：

1. 工具返回图片 URL。
2. 用 `curl -L -o "outputs/ozon/<商品>_<日期>/images/<IMAGE_NAME>" "<图片URL>"` 下载到本地 `images/` 目录。
3. 在 image_results.md 记录：图片编号、所用工具（`image_gen` / `image_edit`）、参考图 URL、落盘本地路径、文件字节数。
4. 以落盘本地路径为最终产物；不要把工具返回的临时 URL 直接交付给用户。

- 产品比例是否明显错误
- 接口、按钮、支架、线材是否被画错
- 是否出现不存在的配件

- 是否有明显变形

### Ozon 主图检查

# 执行原则

优先级从高到低：

1. Ozon 合规
2. 产品真实性
3. 图片信息可追溯
4. 不虚构参数
5. 图片单张独立
6. 俄语可用
7. 富文本结构清晰
8. 出图效率

如果合规和美观冲突，以合规为准。
如果真实性和氛围感冲突，以真实性为准。
如果图片识别和用户确认冲突，以用户确认信息为准，并在报告中标注差异。
如果参数不确定，以“待确认”为准，不要编造。
