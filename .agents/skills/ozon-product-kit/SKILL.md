# ozon-product-kit — Ozon 商品卡一键生成 Skill

## 目标

本 skill 是 Ozon 商品卡总控工作流。用户只需要提供以下任意一种输入：

- 一张或多张产品图
- 一个商品链接
- 一段简单中文说明
- 产品图 + 少量参数
- 商品链接 + 少量补充说明

本 skill 自动完成：

1. 识别商品和图片中的可见信息
2. 提取图片里的尺寸、参数、卖点、型号、材质、包装清单等文字信息
3. 区分“已确认 / 图片识别待核对 / 待确认”
4. 设计 10 张 Ozon 商品卡图片方案
5. 调用豆包内置图片工具（`image_gen` 文生图 / `image_edit` 参考图编辑）逐张生成图片
6. 生成俄语 Ozon 标题、简介、卖点、商品描述、营销文本
7. 生成 30 个以内俄语主题标签
8. 生成 Ozon 富文本内容结构
9. 输出完整路径、文案和复核清单

# 依赖（出图后端）

本 skill **不依赖任何外部出图脚本**（已弃用旧的 `gen-image/generate.py` 及其第三方 API）。
直接使用豆包内置图片工具：

- `image_gen`：文生图。无产品图时做概念图 / 场景氛围图 / 干净排版底图。
- `image_edit`：参考图编辑（图生图）。**有产品图时一律走这条**，把产品实拍图作为参考锚点，保持产品外观一致。

入参映射（旧 gen-image CLI → 豆包工具）：

| 旧 gen-image 参数 | 豆包工具对应 |
|---|---|
| `--mode create` | `image_gen(prompt, width, height, model_version)` |
| `--mode edit --image X` | `image_edit(prompt, image_reference_url_list=[X_url], width, height, model_version)` |
| `--mode mask`（去水印 / 换背景 / 局部改） | `image_edit`，在 prompt 里用自然语言圈定只改哪一块，无独立 mask 参数 |
| `--size 1080x1440` | `width=1080, height=1440`（3:4 竖版） |
| `--n 1` | 每次 request 只出 1 张 |
| `--name 01_main.png` | 生成后把返回 URL 落盘为该文件名 |

固定出图参数：

- `width=1080, height=1440`（Ozon 3:4 竖版；用户指定其它比例时再改）。
- `model_version` 分支规则（默认）：
  - `image_edit`（有参考图：主图 / 保真编辑 / 局部修改）→ `seedream_5.0_flash`：快且产品一致性稳。
  - `image_gen`（无参考图：场景图 / 概念图 / 排版底图）→ `seedream_5.0_pro`：质感更好。
  - 用户明确指定模型时以用户为准；`seedream_5.0_pro` 调用失败（如会员权限不足）时回退 `seedream_5.0_flash`。

本地产品图是参考图时的前置步骤（必须）：

1. 本地图片不能直接塞进 `image_edit.image_reference_url_list`，必须先调用 `FileBatchUpload` 把本地产品图上传，拿到 `https://` URL。
2. 把该 URL 填进 `image_reference_url_list`。
3. `image_reference_url_list` 最多 10 张；产品图 + 场景图可一起传入做多图参考。

落盘（必须）：

1. 生图工具返回的是图片 URL，不是本地路径。
2. 用 `curl -L -o "<输出目录>/images/<文件名>" "<图片URL>"` 下载到 `images/` 目录。
3. 以落盘后的本地路径为准写入 image_results.md / run_report.md；不要把临时 URL 当最终产物交付。

Ozon一键生成：

6. 缺少参数时不中断流程，但要标记“待确认”。

# 支持的输入模式

## 1. 产品图模式

用户上传一张或多张产品图。

处理方式：

1. 识别商品类型、颜色、结构、可见配件、可见文字。
2. 对图片进行视觉分析和文字提取。
3. 提取图片中出现的尺寸、参数、卖点、型号、材质、包装清单、安装步骤等。
4. 将清晰可见且合理的信息列入“已确认信息”。
5. 将模糊、不完整、有遮挡或可能识别错误的信息列入“图片识别待核对”。
6. 将图片无法确认的信息列入“待确认信息”。
7. 生成图片时优先使用 `image_edit`，并把产品图作为参考图。
8. 不要用纯 `image_gen` 重新画产品主图。
9. 不要虚构图片中不存在的配件、功能、品牌和参数。

## 2. 链接模式

用户提供商品链接。

处理方式：

1. 尝试读取链接内容。
2. 提取商品标题、主图、详情图、参数、包装清单、卖点。
3. 如果页面有多张图，优先选择最清晰、最接近商品白底图的图片作为产品参考图。
4. 如果链接无法访问、需要登录、验证码或反爬，则提示用户上传产品图或截图。
5. 链接中没有明确写出的参数不能当作确定信息。
6. 不要复制竞品品牌、店铺名、水印、公司名和侵权词。

## 3. 简单文字模式

用户只提供一句话，例如：

```text
280KG 防水磁力锁，生成一套 Ozon 商品卡。
```

处理方式：

1. 根据文字生成商品理解和图片方案。
2. 缺少产品图时，只能生成方案、文案和场景示意图。
3. 主图、细节图、尺寸图必须提醒用户需要真实产品图。
4. 不要生成“看起来像真实产品”的主图来冒充真实商品图。
5. 所有无法确认的信息写入“待确认”。

## 4. 图 + 参数模式

这是推荐模式。

用户提供产品图，同时补充参数，例如：

```text
商品：黑色三脚架自拍杆
参数：120cm，24cm收纳，7节伸缩，1/4螺丝，铝合金+ABS
要求：生成10张Ozon商品图、俄语listing、标签、富文本
```

处理方式：

1. 产品图作为外观参考。
2. 用户参数作为已确认信息。
3. 图片中文字和参数作为补充来源。
4. 根据商品类型自动设计 10 张图。
5. 调用豆包 `image_edit` 逐张出图。
6. 生成俄语商品资料。

# 图片文字 / 尺寸 / 卖点提取规则

这是本 skill 的关键规则。

## 必须从产品图中提取的信息

如果图片中出现以下内容，必须尝试提取：

- 商品名称
- 型号
- 尺寸，例如长度、宽度、高度、厚度、直径
- 重量
- 材质
- 颜色
- 节数、档位、数量
- 功率、电压、电流、电池容量
- 接口类型，例如 Type-C、USB、1/4 螺丝
- 防水、防尘、耐高温、承重等功能卖点
- 适用设备
- 适用场景
- 安装步骤
- 包装清单
- 警示说明
- 认证标志

## 提取结果必须分级

提取后生成 `image_extracted_info.md`，结构如下：

```markdown
# 图片识别信息

## 图片来源

## 可见商品结构

## 图片文字提取表

| 原图文字 | 识别结果 | 中文解释 | 俄语可用表达 | 可信度 | 使用状态 | 备注 |
|---|---|---|---|---|---|---|

## 已确认信息

## 图片识别待核对

## 明确禁止复制的信息

## 待确认信息
```

## 可信度规则

### 高可信，可作为已确认信息

满足全部条件才可作为已确认信息：

1. 图片中文字清晰可读。
2. 数字和单位完整，例如 `120cm`、`24cm`、`207g`。
3. 与商品外观和类别不冲突。
4. 不是价格、联系方式、二维码、店铺名、水印、竞品品牌。

### 中可信，作为“图片识别待核对”

以下情况不能直接写成确定卖点：

1. 字体模糊。
2. 被遮挡。
3. 数字不完整。
4. 单位不清楚。
5. 可能是图片背景里的无关文字。
6. 参数与商品外观看起来冲突。

### 低可信，不能使用

以下内容必须丢弃：

1. 价格。
2. 折扣。
3. 联系方式。
4. 店铺名。
5. 公司名。
6. 水印。
7. 二维码。
8. 平台促销标签。
9. 竞品品牌。
10. 识别明显错误的乱码。

## 图片中文字如何使用

1. 可以把中文参数翻译成俄语 listing。
2. 不要把中文直接放到最终 Ozon 文案里。
3. 不要让 AI 在生成图里重新绘制中文。
4. 尺寸、参数、卖点可以用于文字内容，但必须注明来源是图片识别。
5. 对重要参数，最终输出中要提示人工复核。

示例：

如果图片中写着：

```text
120cm / 24cm / 7节伸缩 / 1/4螺丝 / 207g
```

可以在 `image_extracted_info.md` 中写：

```markdown
已从图片中识别到：展开高度 120cm、收纳长度 24cm、7 节伸缩、1/4 螺丝接口、约 207g。建议人工复核后用于最终上架参数。
```

俄语 listing 可写：

```text
Высота в разложенном виде — до 120 см, длина в сложенном виде — около 24 см, 7 секций, универсальный винт 1/4".
```

但生成图片时不要让 AI 直接写这些数字。

# 信息可信度分级

所有商品信息必须分为四类。

## 用户确认信息

用户明确提供的信息。优先级最高。

## 图片识别信息

从产品图文字、参数表、包装图或说明图中识别的信息。

图片识别信息可以使用，但重要参数需要在最终结果中提示人工复核。

## 合理推断信息

根据外观和商品类别可以合理判断的信息，例如：

- 黑色外壳
- 三脚架结构
- 可伸缩结构
- 玻璃门安装场景
- 桌面使用场景
- 便携收纳场景

合理推断信息可以谨慎写入描述，但不要写成绝对承诺。

## 待确认信息

以下信息如果用户、链接、图片都没有明确提供，不得编造：

- 净重
- 尺寸
- 材质
- 承重
- 功率
- 电池容量
- 防水等级
- 认证
- 包装清单
- 是否含遥控器
- 是否含手机夹
- 是否含安装螺丝
- 是否支持某具体型号
- 质保时间
- 品牌授权

待确认信息必须在最终结果中单独列出。

# Ozon 图片硬性要求

## 官方规格（来源：Ozon 帮助中心《对图片的要求》）

本地知识库：`ozon-help-kb/markdown/products/requirements/media/image-requirements.md`

| 参数 | 要求 |
|---|---|
| 格式 | JPEG / JPG / PNG / HEIC / WEBP |
| 比例 | 全部类目竖版 3:4（主图不符会被 8 点拉伸或上下留白） |
| 分辨率 | 服装/鞋子/配饰 ≥900×1200px；其他类目 200×200 ~ 4320×7680px |
| 大小 | ≤10MB |
| 数量 | 主图 1 张；附加图 ≤29 张（建议 ≥2 张）；**商品图片总数不得低于 6 张（用户业务硬性要求）** |
| 主图 | 1 张、彩色、清晰、无水印、无文字，商品完整正面展示 |
| 附加图 | 无水印；与主图商品一致；不得含联系方式/链接/促销 |
| 禁止 | 黑白/模糊/低质照片、家居背景（地毯/家具阴影）、3D 草图、酒类、不含商品的图、他人商品图、暴力内容；18+ 商品私密部位须模糊处理 |

所有商品图必须遵守：

1. 单张独立图片，不要拼宫格。
2. 竖版 3:4。
3. 推荐尺寸：`1080x1440`（注意 1024×1536 是 2:3，不是 3:4，勿用）。
4. 背景白色或浅色。
5. 白色或透明商品可使用深色背景。
6. 服装、鞋类、配饰类目可使用灰色背景 `#f2f3f5`。
7. 图片清晰，不要模糊。
8. 不要黑白照片。
9. 不要价格。
10. 不要折扣。
11. 不要联系方式。
12. 不要链接。
13. 不要二维码。
14. 不要购买引导，例如“购买”“立即下单”“联系卖家”。
15. 不要中文。
16. 不要水印。
17. 不要品牌 logo，除非用户明确拥有品牌并要求保留。
18. 不要公司名、工厂名、店铺名。
19. 不要侵权商标。
20. 主图不要大段文字。
21. 主图商品不要贴边，四周保留安全边距。
22. 重要细节不要靠近四角，避免被平台徽章遮挡。
23. 不要虚构配件。
24. 不要虚构功能。
25. 不要让 AI 自动生成复杂俄文和参数数字。

# 图片来源合规（必做）

生成任何图前，先登记参考图来源并分类：

| 来源类型 | 标记 | 用途 |
|---|---|---|
| 自有货源实拍图 / 供应商授权图 | `可上架` | 可作生成锚点，最终上架图必须全部出自此类 |
| 竞品下载图 / 他人商品图 | `仅参考` | **禁止作为生成锚点**；只允许用于提取卖点、参数、场景创意和风格参考 |
| 无来源的网图 | `待确认` | 不得使用，先向用户核实来源 |

强制规则：

1. 竞品图只能用于"读懂商品卖点"，不得以其画面为锚点生成上架图（Ozon 禁止他人商品图，改水印/重绘不改变侵权性质）。
2. 上架前核验：最终交付图集的生成锚点必须全部来自 `可上架` 来源；存在 `仅参考` 锚点时，交付说明必须标注"仅供内部参考，不可上架"。
3. 来源登记写入 image_results.md 的"图片来源"字段。

# 图片文字规则

## 文字使用边界（用户已确认口径）

- **第 1 张主图（白底图）**：严格无文字。
- **附加图（第 2 张起）**：可以带文字（俄语卖点 / 参数 / 说明），按"卖点文字锁定表"逐字生成，生成后必须 OCR 核对。

## 文字来源（禁止临时编造）

1. 所有出现在图上的文字（俄语卖点、参数、说明）必须来自"商品理解简报"（Step 3 的 image_extracted_info.md / product_brief.md 已确认信息），生成前先锁定到 image_plan.md 的"卖点文字锁定表"。
2. **真实数据（尺寸、材质、重量、容量、认证等）只有两种来源**：用户确认，或图片高可信识别；两者皆无时，该图只出无字底图并在交付中标注"[待补]"，等待用户提供数据后再加文字，**严禁 AI 编造**（例：AI 曾自写 330mm 尺寸标注，属违规）。
3. 俄语文字由 AI 生成有错字风险：带文字图生成后必须逐张 OCR 核对，错字/乱码/重复立即重做（见 Step 8）。

## 一般规则

1. 主图不放文字。
2. 尺寸图缺真实尺寸数据时，只生成干净底图 + "[待补]"标记；有数据后按锁定表加俄语标注。
3. 富文本底图可以预留标题区、参数区、卖点区，但不要让 AI 写具体文字（后期排版）。
4. 如果用户要求直接出带文字图片，必须提醒：AI 可能生成错误文字，生成后需核对。

# 产品一致性规则

如果用户提供产品图，默认所有图片都使用 `image_edit` 参考图编辑。

- 产品颜色
- 产品比例
- 产品结构
- 接口位置
- 螺丝孔
- 按钮
- 线材
- 支架
- 表面纹理
- 材质质感

禁止：

- 把产品画成不同型号

- 改变产品颜色
- 改变核心结构
- 把产品夸张变形
- 把尺寸比例画得明显不合理

# 总工作流程

## Step 1：解析输入

读取用户输入中的：

- 商品链接
- 产品图片路径
- 商品中文名
- 商品型号
- 已知参数
- 图片中可见文字
- 颜色
- 材质
- 适用场景
- 包装清单
- 禁止内容
- 目标平台
- 目标语言

默认：

- 目标平台：Ozon
- 目标语言：俄语

## Step 8：图片质量检查

每张图生成后必须检查：

### 基础合规

- 是否是单张独立图片
- 是否 3:4
- 是否清晰

- 是否没有购买引导

- 产品颜色是否一致
- 产品结构是否一致
- 产品比例是否明显错误
- 接口、按钮、支架、线材是否被画错
- 是否出现不存在的配件
- 是否出现不存在的功能
- 是否有明显变形

### 画面完成度

- 关键主体完整置于安全边界内，四周边距均衡，背景自然铺满画布
- 需要文字的画面：文字形成清晰可读的主标题、辅助信息和行动层级（如有），无乱码 / 错字 / 重复生成
- 纯视觉画面：图形、色彩、材质和空间关系承载信息
- 有人物时：五官结构自然、手部五指关系自然、肢体比例协调
- 产品与背景光影融合自然，无生硬抠图感、无水印黑框
- 参考图强制锚点（产品身份）在生成图中完整保留

### 文字核对与真实数据（附加图必查）

- 画面含生成文字时：用 OCR 逐字核对，俄语拼写正确、无乱码、无重复、无遗漏
- 核对画面文字与"卖点文字锁定表"一致，无临时编造内容
- 尺寸/材质/重量等真实数据：确认来自锁定表（用户确认或图片高可信识别），无 AI 编造数字
- 主图（第 1 张）：确认无任何文字

### Ozon 主图检查

主图额外检查：

- 是否无文字
- 是否白底或浅底
- 是否产品居中
- 是否四周留白
- 是否重要部分没有靠近角落

如果图片失败，记录失败原因，重新生成。每张图最多重试 2 次。

# 执行原则

优先级从高到低：

1. Ozon 合规
2. 产品真实性
3. 图片信息可追溯
4. 不虚构参数
5. 图片单张独立
6. 俄语可用
7. 富文本结构清晰
8. 出图效率

如果合规和美观冲突，以合规为准。
如果真实性和氛围感冲突，以真实性为准。
如果图片识别和用户确认冲突，以用户确认信息为准，并在报告中标注差异。
如果参数不确定，以“待确认”为准，不要编造。
